### D-B4 — DRF pagination (B4)

1. Create `backend/webcoder_api/pagination.py` with two classes: `StandardPageNumberPagination(PageNumberPagination)`: `page_size=20`, `page_size_query_param="page_size"`, `max_page_size=100`; `NewestFirstCursorPagination(CursorPagination)`: `page_size=25`, `page_size_query_param="page_size"`, `max_page_size=100`, `ordering="-created_at"` (subclassed per-resource to override ordering).
2. `settings.py` — extend REST_FRAMEWORK with `"DEFAULT_PAGINATION_CLASS": "webcoder_api.pagination.StandardPageNumberPagination"`, `"PAGE_SIZE": 20`. Every list endpoint is a router-registered ViewSet/generic, so the default instantly paginates `/api/v1/problems/`, `/api/v1/tags/`, `/api/v1/testcases/`, `/api/v1/submissions/`, `/api/v1/users/`, `/api/v1/users/admin/manage/` with zero per-view edits.
3. Cursor overrides ONLY on the three newest-first feeds where rows drift across pages: `SubmissionViewSet.pagination_class` = cursor subclass with `ordering="-submission_time"` (matches Meta ordering at `submissions/models.py:80`); forum Post list (ordering `created_at`); NotificationViewSet list (ordering `-created_at`).
4. Frontend contract: page-number endpoints return `{count, next, previous, results}`; cursor endpoints `{next, previous, results}` — the Next.js data layer keys off presence of `"count"`; `max_page_size=100` blocks whole-table dumps.
5. Tests (`backend/webcoder_api/test_pagination.py`, pytest-django already pinned): problems list returns wrapped shape, `?page_size=1000` clamped to 100, `?page=9999` → 404, submissions returns cursor shape honoring `?cursor=`, users paginated, anonymous problem list still 200. Also slim the submissions list payload: a `SubmissionListSerializer` without `code`/`test_results` for the list action (full serializer for retrieve) — today `/my-submissions` fetches the user's entire history **with full source code** every visit.

### D-B8 — Leaderboard app (B8)

New app `backend/leaderboard/` (add to INSTALLED_APPS).

**Model** (`leaderboard/models.py`): `LeaderboardEntry`: `user` OneToOneField(AUTH_USER_MODEL, on_delete=CASCADE, related_name="leaderboard_entry"); `solved_count` PositiveIntegerField(default=0); `total_points` PositiveIntegerField(default=0); `last_solved_at` DateTimeField(null=True, blank=True); `updated_at` auto_now; Meta `ordering=["-total_points","-solved_count","last_solved_at"]` (earlier solver wins full ties), index on `("-total_points")`.

**Scoring rule (v1, Codeforces-lite):** a solve = `Submission.verdict==AC` on a Problem with `status==APPROVED`; points credited once per (user, problem) = sum of that problem's `TestCase.points` (default 10 each); partial `Submission.score` ignored for the leaderboard.

**Aggregation** (`leaderboard/aggregation.py`, single SQL pass, no N+1): `points_sub = TestCase.objects.filter(problem=OuterRef("problem")).values("problem").annotate(p=Sum("points")).values("p")`; `solves = Submission.objects.filter(verdict=VerdictStatus.ACCEPTED, problem__status=ProblemStatus.APPROVED).values("user_id","problem_id").annotate(first_ac=Min("submission_time"), points=Subquery(points_sub))`; then `rows = solves.values("user_id").annotate(solved_count=Count("problem_id", distinct=True), total_points=Sum("points"), last_solved_at=Max("first_ac"))` — rows are already deduped per (user, problem) so Sum is exact; upsert via `update_or_create(user_id=…)` and delete entries not in the result.

**Incremental update:** at the terminal-verdict save in `submissions/tasks.py`, when verdict==AC call `transaction.on_commit(lambda: update_user_entry.delay(submission.user_id))` — recomputes only that user's row (idempotent, race-free). **Nightly reconciliation:** `@shared_task recompute_all_leaderboards` full pass, scheduled by celery beat (D-B11).

**Endpoints** (`leaderboard/urls.py`, mounted at `path("api/v1/leaderboard/", …)`):
1. `GET /api/v1/leaderboard/` — ListAPIView, AllowAny, StandardPageNumberPagination page_size=50, queryset `LeaderboardEntry.objects.select_related("user").annotate(rank=Window(RowNumber(), order_by=F("total_points").desc(), F("solved_count").desc(), F("last_solved_at").asc()))` (Postgres window function; DRF paginates window-annotated querysets fine); serializer `{rank, username, solved_count, total_points, last_solved_at}`.
2. `GET /api/v1/leaderboard/me/` — IsAuthenticated; get_or_create then rank = 1 + count of strictly-better entries (points, then solved, then earlier last_solved_at); returns `{rank, solved_count, total_points}`.

**Catalog stats add-on** (in `problems/views.py` list): annotate `submission_count=Count("submissions")` and `solved_count=Count("submissions", filter=Q(submissions__verdict="AC"), distinct=True)` so problem cards can render "X tried / Y solved"; expose via two new ProblemSerializer fields.

**Tests** (`leaderboard/test_leaderboard.py`): double AC on same problem credits once; WA/CE never credit; PRIVATE problem excluded; me/ rank arithmetic incl. tie-break; recompute idempotent; rank column matches ordering.
